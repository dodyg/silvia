# Web pages as project documents

## Goal

A user can add one URL, or paste a list, in **Library**. Silvia downloads each page, keeps its main content as a
document of the project, and from then on treats it like any other file:

- it is indexed, given an overview and added to the graph;
- it is searched and cited;
- conversation memory skips answers that used an older version of it.

Answers cite the page by its title and address, and opening a citation opens the URL in the browser. A page can
be refreshed or removed. A project with web pages exports, imports and duplicates without losing them.

## Out of scope (first version)

- Crawling: following links, depth limits, robots.txt, sitemaps.
- Pages that need a sign-in, cookies or JavaScript to show their content. These are reported as such, not indexed
  empty.
- Scheduled refresh. Refresh is on demand, for one page or all pages. This is the first follow-up.
- Links from graph entities to URLs, discussed separately. Downloaded pages already join the graph through extraction.

## Design

### The database is the record, the folder is a copy

Everything in Silvia's index is keyed by a file path:
- document ids,
- the ETag checks of rescans, overviews and the graph,
- the version check of conversation memory,
- the "modified" date in the context,
- opening and revealing a document.

A web page therefore becomes a **file**, so all of that works unchanged.

But an export copies only `project.db` ([ProjectManager.cs](../../src/Silvia.Core/Projects/ProjectManager.cs)), and an
import keeps source folders as absolute paths. So the page's content also lives **in `project.db`**, in a new
`web_pages` table:

- **The table** holds, per page:
  - the URL, final URL and title;
  - the extracted Markdown (or the original bytes for PDF/Office files);
  - the content type, a content hash, and the HTTP `ETag` / `Last-Modified`;
  - the fetch date, its status (`ok`, `failed`, `needs-browser`) and the last error;
  - the relative file name.
- **The files** are written to `<project folder>/web/` and indexed from there.
- **When the runtime opens**, it writes any file that is missing from the table (after an import or a duplicate),
  and queues the pages whose document is not indexed.
  - Their document ids change with the folder, so an imported project re-embeds its web pages once.
  - That costs one embedding pass, plus overview and graph calls if those are on. It is acceptable for a move
    between machines.

The `web/` folder is **not** a row in `sources`. It does not appear in the folder list, cannot be removed by
mistake, and is unaffected by the hourly rescan. Pages go through the queue's existing per-file `Upsert` and
`Delete` jobs.

### Fetching

- **`WebFetcher`** in `Silvia.Core/Ingestion`, over an injected `HttpClient`, so tests use a fake handler.
- **Request limits:**
  - `http` and `https` only;
  - 30 s timeout and at most 5 redirects;
  - at most 20 MB;
  - no cookies, and a `Silvia/<version>` user agent.
- **Local and intranet addresses are allowed.** Reaching an intranet is the point for a desktop app.
- **Conditional refresh:** send `If-None-Match` / `If-Modified-Since`. A `304` changes nothing.
- **Write only when the content changed.** If the content hash is the same, the file is not rewritten. A new write
  time would otherwise re-run the overview and the graph for nothing.

### Turning a response into a document

| Content type | Saved as |
|---|---|
| `text/html` | Main content extracted, converted to Markdown, `.md` |
| `text/markdown`, `text/plain` | As is, `.md` / `.txt` |
| `application/pdf`, `.docx`, `.xlsx`, `.pptx` types | The original bytes, with that extension, read by the existing parsers |
| Anything else | Refused: "Silvia cannot read this type of page" |

- **HTML extraction:**
  - Extract the main article (a readability-style extractor), so menus, footers and cookie banners are not indexed.
  - Convert it to Markdown, keeping headings, lists and tables. Headings drive the section paths and chunking.
  - Candidates are **SmartReader** (a readability port) and **ReverseMarkdown**. Check their licences and
    maintenance before adding them.
- **The top of each `.md` file** names its source: a level-1 heading with the page title, then a line
  `Source: <url> · fetched <date>`.
- **A page whose extracted text is nearly empty** (for example under 200 characters) gets status `needs-browser`
  and is not indexed. Such pages are usually built by script or behind a sign-in.
- **File name:** `<host>-<slug>-<short hash of URL>.<ext>`, readable in Activity, and unique per URL.

### How a web page shows in answers

- **Context line:** a passage of a web page is labelled with its title, host and fetch date instead of the file
  name and modification date. For example: `[3] Pricing — example.com › Plans (web page, fetched 2026-11-03)`.
  Readers and the model can then see that it comes from the web.
- **Citations:** the citation DTO gains an optional `url`. The chat's evidence panel shows it, and **Open** opens
  the URL in the browser. **Reveal** stays for the saved copy.
- **Opening a URL:** a new `library.openUrl` call opens only URLs that belong to the project's web pages, the same
  guard `openDocument` applies to files.

## Steps

- [x] **1. Spike the extraction.**
  - Try SmartReader + ReverseMarkdown on about ten real pages: a docs site, a news article, a wiki page, a page with
    tables, a script-built page.
  - Record the result in this plan, and choose the libraries or a fallback (AngleSharp with our own
    boilerplate rules).
  - **Result** ([spike/Silvia.WebSpike](../../spike/Silvia.WebSpike/Program.cs), 2026-11-03). Licences: SmartReader 0.11.1
    is Apache-2.0 (released 2026-07), ReverseMarkdown 6.3.0 is MIT (2026-10). Both are maintained, and both build on
    AngleSharp 1.5.2. Chosen: both, plus our own fallback rules.
    - Docs pages (Microsoft Learn, Python docs, SQLite), Wikipedia articles, a GitHub README and RFC 9110 extract
      cleanly, with headings and tables.
    - SmartReader **drops data tables**: the Wikipedia population list lost its whole table. The fallback: when the
      extract has no table and the page's own main region (`#mw-content-text`, `main`, `[role=main]`, a single
      `article`) has one, the cleaned region is used instead.
    - News front pages (BBC, Guardian): SmartReader finds nothing useful. The cleaned main region gives the list of
      headlines, which is indexed as such.
    - Links and images are removed before conversion; an image keeps its short alt text. Link targets otherwise
      fill the passages.
    - **`Accept` must not name `text/markdown`**: react.dev answers 404 to it. A browser-style `Accept` is sent.
    - A script-built page is covered by the unit test (an empty root `div`), not by a live page.
- [x] **2. Storage.**
  - Add the `web_pages` table in `ProjectDatabase.Migrate` and bump `CurrentVersion`.
  - Add a `WebPageStore`: add, list, get by URL or by document id, update after a fetch, remove.
  - Add the `<project folder>/web/` path to the runtime.
- [x] **3. `WebFetcher` and `WebPageConverter`.**
  - Fetch with the limits above and conditional requests.
  - Map content types to documents as in the table above, and detect `needs-browser`.
  - Unit tests over a fake `HttpMessageHandler`: HTML, PDF, `304`, redirect limit, size limit, a refused type,
    an empty page, a timeout.
- [x] **4. Runtime.**
  - `AddWebPagesAsync(urls)`, `RefreshWebPageAsync(id)`, `RefreshAllWebPagesAsync()`, `RemoveWebPage(id)`,
    `WebPages()`.
  - Fetching runs in the background like indexing; failures show in Activity with the URL.
  - On open, write the missing files and queue the pages that are not indexed.
  - Remove deletes the row, the file and the document, and queues a `Delete`.
  - *As built:* a download is a `Fetch` job of the ingest queue (its path is the address), so it survives a restart,
    keeps the project busy, and a failure shows in Activity with the URL. Permanent failures (4xx, refused type,
    `needs-browser`, size or redirect limits) are not retried. The methods only queue work, so they are
    synchronous: `AddWebPages`, `RefreshWebPage`, `RefreshAllWebPages`, `RemoveWebPage`, `WebPages`. The
    runtime also runs `ProjectDatabase.Migrate` on open, which was only run on create before, so older projects
    get the `web_pages` table.
- [x] **5. Answers and citations.**
  - Label web passages in `PromptAsync` with title, host and fetch date.
  - Add `Url` to the cited chunk and citation DTOs.
  - Add `library.openUrl` with its guard, and allow `openDocument` / `revealDocument` under the `web/` folder.
- [x] **6. RPC and Library screen.**
  - `library.listWebPages`, `addWebPages`, `refreshWebPage`, `refreshWebPages`, `removeWebPage`.
  - In Library, add a **Web pages** section: an input for one URL or a pasted list, then a row per page with its
    title, address, fetch date, status and **Refresh** / **Remove**.
  - In Chat, the evidence panel opens the URL for a web citation.
- [x] **7. Export, import and duplicate.**
  - Check that the pages travel in `project.db`, and that the first open of the copy writes the files and indexes
    them under the new folder.
  - Make sure the original project's `web/` folder is never read by the copy.
- [x] **8. Help.**
  - Update **Getting started** (adding web pages), **The screens** (Library) and **Troubleshooting**
    (`needs-browser`, refused types).
  - Update **Privacy**: fetching a page is an outbound request to that site, and sends nothing from the project.
- [x] **9. Tests and verification.**
  - *As built:* `library.addWebPages` takes at most 200 addresses per paste (first open question).
  - Core tests:
    - a page is added, indexed, searched and cited with its URL;
    - an unchanged refresh rewrites nothing and queues no overview;
    - a changed refresh re-indexes, and memory stops recalling the old answer;
    - remove clears the document;
    - an import of the project indexes the pages under the new folder.
  - An RPC test for `openUrl` refusing a URL that is not one of the project's pages.
  - Run the full core, app and frontend tests.
  - Check the Library screen in the mock build.
  - *Result (2026-11-03):* 138 .NET tests pass (1 Release-only performance gate skipped), 12 frontend tests pass,
    the mock build succeeds; Library and the chat evidence panel were checked in a browser on the mock build.

## Risks

> [!WARNING]
> **Prompt injection.** A web page is written by someone else. The context already treats documents as data. The web
> label lets the model and the reader weigh a web passage accordingly. Facts and the system prompt still take
> precedence.

- **Extraction quality varies by site.** Step 1 is there to find out early. A page whose extract is poor can still
  be checked in Library → document → passages, as any file can.
- **Cost of refresh with overviews and the graph on.** Writing only on a content change keeps refreshes of
  unchanged pages free.
- **Size of `project.db`.** It grows by the size of the extracted pages, plus any PDF/Office bytes, up to 20 MB
  each. This is fine for tens or hundreds of pages. If it becomes a problem, a later step can keep binaries out of
  the database.

## Open questions

- Should a paste of many URLs have a limit, or ask for confirmation above some number, because of overview and
  graph costs?
- Should **Refresh all** also run at startup when pages are older than some age, or wait for scheduled refresh?
  - *Answered (2026-11-05):* both. The project setting **Refresh web pages after (hours)** (`WebRefreshHours`, 24 by
    default, 0 for on demand only) downloads again every page older than that when the project opens and at each
    hourly rescan.
